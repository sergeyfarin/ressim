# OPM Flow Reference Pipeline

OPM Flow is the industrial open-source simulator used as offline ground truth. The browser never runs OPM — precomputed JSON artifacts are committed into the frontend catalog. Every committed artifact is `status: "parsed"`, unit-checked and provenance-stamped (#20, 2026-09-24).

## Requirements

- `flow` binary installed locally; check `flow --version`. Not guaranteed present in every sandbox, but was available and used for the 2026-07-16 real runs (`flow 2026.04`) — don't assume it's absent without checking.
- Python via `uv` (project convention for all Python tooling). Dev dependency group `dev` (pytest) — run tests with `uv run pytest` from `tools/opm_flow/`.

## Commands (from repo root)

```bash
# generate an Eclipse-style deck from a ResSim case definition
uv run --directory tools/opm_flow python -m opm_flow_tool.cli generate-deck wf_bl1d --output tmp/opm-flow-runs/decks/wf_bl1d.DATA
# run flow on a case
uv run --directory tools/opm_flow python -m opm_flow_tool.cli run-flow wf_bl1d
# build frontend artifacts (also: pnpm run opm:artifacts / opm:deck)
uv run --directory tools/opm_flow python -m opm_flow_tool.cli build-artifacts all
```

## How the pieces connect

| File | Role |
|---|---|
| `tools/opm_flow/opm_flow_tool/cases.py` | `OpmCase` definitions: the deck (inline text or a committed `deck_source`), `flow_args`, `curve_display` |
| `tools/opm_flow/opm_flow_tool/vectors.py` | The vector contract: unit, allowed panels and naming token for each summary mnemonic |
| `tools/opm_flow/opm_flow_tool/summary.py` | `.RSM` text-summary parser |
| `tools/opm_flow/opm_flow_tool/artifacts.py` | `build_artifact()` writes `src/lib/catalog/opm-flow-results/<case>.json` with units, provenance and `deckHash` |
| `src/lib/ressim/src/tests/opm_small_direct.rs` | Writes the committed decks from ResSim's own simulator setup |
| `src/lib/catalog/opmFlowArtifacts.ts` | `resolveScenarioReferenceSeries()` renders the `status === 'parsed'` series a scenario declares |
| `src/lib/catalog/opmFlowTwin.ts` | Grades a scenario variant against its artifact |

Rules that hold for every use:

- An artifact is drawn only when a scenario lists it in `referenceSources`. Nothing is matched
  implicitly.
- Adding a summary vector means adding its row to `vectors.py` first. A unit mismatch makes the
  artifact `status: "error"` and `build-artifacts` exits 1.
- Surface volumes (SM3) and reservoir volumes (RM3) never feed the same axis.
- For a new case, prefer a committed deck generated by `opm_small_direct.rs` over inline deck
  text: its inputs cannot disagree with the engine.

The full description of each piece is in `internals.md` beside this file. Read it before editing
`cases.py`, `vectors.py`, `summary.py` or `artifacts.py`, before adding a curve or an x-axis
mapping, and before writing a deck feature (gravity, layered grids, multi-completion wells,
capillary pressure, reservoir-volume targets).

### Gates

- `tools/opm_flow/tests` (pytest; PR CI step "Run OPM artifact pipeline tests"): the unit contract, every case's mappings against it, every committed artifact `parsed`, schema-current, attributed, and generated from the deck its case holds now (deck edited without a Flow re-run fails).
- `src/lib/catalog/opmReferenceWiring.test.ts` (Vitest, also on master): every artifact is declared by its scenario, lands on a panel that scenario draws, can be placed on the axis its chart opens on, and has one unit per panel; committed-deck artifacts re-hash their deck file.

## Deck pitfalls this repo has shipped

Check a new or edited deck against each one. The full entries, with symptoms and the post-fix
validation, are in `deck-pitfalls.md` beside this file.

- `COMPDAT` item 9 is the wellbore **diameter** and items 7-8 are defaulted (`2*`). A radius in
  item 8 is read as the connection factor.
- A rate-controlled well must hold its target rate. Wells pinned at their BHP limits from day 1
  mean the deck is wrong.
- `PVDO` Bo values must be monotonic; Flow rejects a flat table.
- `TABDIMS` must match the number of tables the PVT and SCAL keywords supply.
- Depth datums agree across `TOPS`, `EQUIL`, `RSVD` and `WELSPECS`; SPE1 Case 1 needs `DRSDT 0`.

## Adding a case

1. Prefer a small-direct case: add it to `CASES`/`build` in `opm_small_direct.rs`, mirroring the worker's `configureReservoirSimulator` order, and regenerate the decks (`OPM_SMALL_DECK_DIR=$PWD/opm/reference-decks/small-direct OPM_SMALL_DECK_LAYOUT=legacy cargo test --release --manifest-path src/lib/ressim/Cargo.toml opm_small_direct_write_decks -- --ignored`). The legacy layout keeps the five wasm-preset decks in their top-level directories; without it the writer creates duplicates under `small-direct/`. Any scenario input that is not a scalar (a PVT table) goes in a committed fixture both sides assert against (`dep-pvt-tables.json`).
2. Add the `OpmCase` (deck via `_committed_deck`), run `run-flow <key>` then `build-artifacts <key>`, register the JSON in `opmFlowArtifacts.ts`, declare it on the scenario, and extend `EXPECTED` in `opmReferenceWiring.test.ts`.
3. Grade ResSim against the same run with `compare_small_direct.py` and record it in `opm/reference-decks/small-direct/README.md`.

## Units

Enforced, not advisory: see the vector contract above. OPM decks are METRIC (bar, m, Sm³/day); `vectors.py` is the single statement of what unit each vector must carry.

## FIM-vs-OPM solver comparison (separate use case)

For solver-convergence benchmarking (not product artifacts): `opm/reference-decks/` holds the gas-rate and water-pressure control decks plus `small-direct/` (the cross-solver scorecard, `scripts/validate-cross-solver.sh`); `scripts/opm-ressim-compare.sh` runs a side-by-side. OPM source checkouts live under `OPM/` at repo root for algorithm reference. Useful flow flags for diagnosis: `--solver-verbosity=3 --time-step-verbosity=3`. OPM's benchmark to beat: ~2.5 Newton iterations/step, zero cut timesteps on SPE1-class cases.

Related docs: `docs/OPM_FLOW_MINIMAL_MAPPING.md` (solver mapping), `docs/FIM_OPM_ALIGNMENT_STRATEGY_2026-04-26.md` (track-OPM vs originality policy).
